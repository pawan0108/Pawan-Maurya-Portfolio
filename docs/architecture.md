# Architecture and development conventions

Phases 02–10 establish source boundaries, content contracts, responsive design/motion, quality verification, and local release setup.

## Source ownership

Supplied-backend update: the user's Apps Script requires all four visitor fields including Phone and returns `{ success, message }` JSON. `sendContactMessage.js` now parses that exact contract and returns its message; no status/plain-text guessing remains. `ContactForm` requires Phone and uses the returned message. `contact-integration.md` records the live GET-only health check and limits. The visitor's required phone field is independent of the profile's personal-phone display flag.

Restored contact functionality: `sections/contact/ContactForm.jsx` owns local submission state; `sendContactMessage.js` posts the original name/email/phone/message FormData contract to the endpoint in `data/contact.json`, recovered from Git. Native validation, duplicate-send guard, timeout, unmount cancellation, failure preservation, and readable response confirmation are implemented. Do not replace this form with only a mailto link again. Browser tests intercept requests; no actual email was sent. The existing Apps Script service is a backend dependency, not a newly created account.

Motion correction: hero entry is now 650ms with 70ms staggering, scroll entry 520ms with up to 140ms card staggering. Desktop project montage cards visibly float over 7s/9s when the hero is onscreen; pause/system preference stop them. No mouse-only gate for essential content, no new animation library. Older motion timing notes below are historical.

User-review correction: all eight personal projects now render through `sections/work/PersonalProjects.jsx` alongside three professional projects. All four education IDs are selected in app config; all 31 skills render with current/MERN/additional grouping. These must not be silently filtered out again. Hero montage uses existing real project captures, replacing the capability boxes; personal identity comes from profile data. `tests/content-completeness.spec.js` guards required content presence. Earlier selective-display decisions below are historical and superseded.

Phase 10 adds build-only `config/release.js`, `vercel.json`, `.nvmrc`, and `src/data/site.json`. Vite owns metadata transformation and robots/sitemap emission; the source HTML keeps charset early. Local sharing/touch assets are generated by `scripts/generate-sharing-assets.mjs` with local fonts. `validate-release.mjs` checks generated output; `check-subpath-release.mjs` builds ignored fixtures and verifies root-independent assets. Defaults target the user-supplied Vercel URL; optional public environment overrides are in `.env.example`. Development and Vercel preview contexts are noindex; normal production is indexable. These modules do not publish or access an account. See `release-handoff.md` for commands and limits.

Phase 09 adds `playwright.production.config.js`, `tests/accessibility.spec.js`, local `scripts/audit-performance.mjs`, and `scripts/optimize-project-previews.mjs`. Production tests target Vite preview on 4173; development tests remain on 5173. Axe rules are a regression aid rather than a compliance certificate. Lighthouse reports and capture candidates stay in ignored `.local` directories; only the small reviewed measurement summary is tracked under `docs/audits/`.

Project previews are local WebP variants (640/800/1280px) with browser-selected srcsets. The complete asset family lives under `src/assets/images/projects/`; data metadata points to each variant, and content validation checks existence. Original capture JPEGs are retained only in ignored candidates for re-encoding. The favicon is a code-native SVG under `public/`. No production URL or robots policy is invented before release configuration.

Tailwind source discovery is explicitly scoped to `src/` from the stylesheet. Documentation and audit/test fixtures cannot accidentally add utility CSS or change production output merely because their prose contains class-like words.

Phase 08 adds `src/hooks/usePageMotion.js` and `src/styles/motion.css`. App owns only a user pause boolean and a main DOM ref; animation frames do not update React state. `data-motion="hero"` marks staggered entry targets, `data-reveal` marks once-only observed regions, and `data-ambient` marks decorative activity. Do not add CSS that hides these elements pending JavaScript. Native animations temporarily enhance visible base styles and are cancelled on focus, preference changes, and cleanup. The hook owns observer/media/visibility/hash/focus subscriptions.

Footer exposes Pause/Resume motion; the root data attribute disables CSS transitions/animations while paused. System reduced motion disables the enhancement and hides the unnecessary pause control. Ambient activity is additionally limited by visibility, viewport intersection, desktop size, and pointer capabilities. Use the existing mechanism for new reveals; do not add per-scroll state, another motion library, or permanent `will-change` layers. `tests/motion.spec.js` covers the fallback and user preference behavior.

Phase 07 removes FoundationSections completely. `src/sections/experience`, `expertise`, `about`, and `contact` own their respective sections. Their editorial text lives in `src/data/sections.json`; factual employment/education stays in `profile.json` and skill provenance in `skills.json`. `siteConfig.featuredEducation` controls which existing records are presented. All four education records and all 31 skills remain preserved; UI emphasizes MCA/BCA, all 18 current technologies, and a compact four-skill MERN background.

Experience dates are formatted from ISO values using explicit UTC month/year; no hardcoded tenure or transition month. Contact uses native mail and external social anchors. Resume/phone/Instagram render only under explicit visibility flags; resume currently remains false because the legacy link could not be verified. No fake form, simulated success, clipboard dependency, or new runtime state is added.

Phase 06 adds `src/sections/work/WorkSection.jsx`, `ProjectRow.jsx`, and `ProjectPreview.jsx`. The work section is removed from FoundationSections. Presentation copy, preview metadata, and evidence live alongside professional project records. Vite imports local preview URLs from `src/assets/images/projects/`; absent previews use a factual text-led fallback. Content validation verifies referenced files. `tests/work.spec.js` covers image loading, attribution, visible ongoing scope, keyboard focus, and touch-to-destination behavior (remote navigation intercepted locally in the test). Asset provenance and recapture instructions are in `project-previews.md`.

Phase 05 adds `src/sections/hero/HeroSection.jsx`, `HeroVisual.jsx`, and locally scoped `hero.css`. `App` composes Hero before the remaining foundation sections. Hero copy and confirmed focus labels live in `src/data/introduction.json` and are included in content validation. The decorative technical illustration stays inside its own component; shared UI remains content-agnostic.

| Location                       | Responsibility                                                             |
| ------------------------------ | -------------------------------------------------------------------------- |
| `src/app/App.jsx`              | Page composition, not section-sized markup                                 |
| `src/app/config.js`            | Public presentation settings, not personal facts                           |
| `src/sections/`                | Dedicated hero, work, experience, expertise, about, and contact components |
| `src/components/layout/`       | Responsive header, disclosure navigation, footer                           |
| `src/components/ui/`           | Container, Button, Badge, SectionHeading                                   |
| `src/data/`                    | Profile, personal/professional projects, skills, JSDoc contracts           |
| `src/styles/globals.css`       | Tailwind entry and base styles                                             |
| `src/styles/tokens.css`        | Implemented charcoal/blue tokens and fluid type/header values              |
| `src/main.jsx`                 | React mounting and global stylesheet import                                |
| `scripts/validate-content.mjs` | Content integrity and ownership checks                                     |

Create shared components, hooks, utilities, assets, and behavioral tests when they have a real responsibility. Do not add empty folders, generic services, or placeholder components. `@/` maps to `src/` in Vite and `jsconfig.json`; native Node scripts use relative filesystem URLs instead.

Dependencies flow from app to sections and shared modules. Shared UI must not import sections or hardcode biography/project facts. Use PascalCase component files, `useName` hooks, stable data IDs as React keys, direct imports, and local state. Add routing/state stores/backends only for a concrete feature.

## Phase 04 assets and interaction verification

Manrope's Latin variable WOFF2 is self-hosted from the Fontsource package using `font-display: swap` and a system fallback. Its SIL Open Font License is retained in `public/licenses/manrope-OFL.txt`. Lucide provides individually imported, tree-shaken generic SVG icons; social links use text with generic symbols because the installed library does not export brand icons.

`Header` owns mobile disclosure state. MatchMedia and keyboard/focus listeners are cleaned up. Escape closes the disclosure and restores toggle focus; breakpoint changes reset stale state and transfer focus to visible navigation. Hidden links are removed from focus order using native `hidden`. No modal focus trap or scroll locking is introduced.

Playwright now covers actual navigation/keyboard behavior, responsive overflow, font loading, and reduced motion in locally installed Chrome. `test:browser` runs the suite; `check:all` combines it with existing checks. Browser availability is required (`channel: chrome`); no browser download occurs automatically. Screenshots and traces are ignored under `test-results/`.

## Tooling and verification

ESLint checks JavaScript, React, hooks, and JSX accessibility. PropTypes boilerplate is not mandatory; document non-obvious shared contracts as needed. ESLint 9 matches the installed React/JSX accessibility plugins' peer ranges; upstream marks this major deprecated. An upgrade to ESLint 10 requires compatible plugins/replacements and verification. This affects development tooling, not the browser runtime.

Prettier owns formatting; `.editorconfig` shares newline/indentation conventions. No Git hooks are installed. React/ReactDOM, selected Lucide icons, and a local Manrope font are runtime assets; lint/format/browser-test tooling does not ship to visitors.

`check:content` validates IDs, dates, web URL syntax, skill provenance, employer associations, optional fields, and incomplete scope. It explicitly guards Yashvi's freelance attribution. It does not verify remote link reachability.

Playwright tests meaningful navigation behavior and responsive shell risks. Avoid tests that merely mirror static markup. `check` runs lint, content validation, formatting checks, and production build; `check:all` adds the browser suite. Browser screenshots are inspected separately from automated assertions.

Use the Node range declared in `package.json`; this workspace uses Node 24. Commit the lockfile; use `npm.cmd ci` for reproducible restoration. `.cmd` avoids this machine's PowerShell script restriction. No credentials/environment variables are needed. Browser-bundled configuration is public; never place secrets there.
